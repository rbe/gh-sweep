# The container engine is Podman, or Docker when Podman is missing

## Rule

The Makefile runs Go and the image through `$(CONTAINER_ENGINE)`. That is Podman when Podman is installed, and Docker otherwise. `CONTAINER_ENGINE=docker` forces Docker. A recipe does not name `podman` or `docker` directly. `make run` runs the program in the container image. The host reads the token from the keyring, and the container gets `GH_TOKEN` by name. The binary on the host is for `make install` only (old label D-9).

## Why

A person who has only Docker can still build and run the tool. The README of the project says so.

## Divergence

The rule is in `project-setup`: `make build`, `make test`, and `make run` call Podman, and Docker is not a second engine. What differs: this project also accepts Docker. Why: the tool is for any person with a GitHub account, and not each of them has Podman. The Make fragments of the installed skills still call `podman` for Python, Ruff, editorconfig-checker, and diff-cover.
