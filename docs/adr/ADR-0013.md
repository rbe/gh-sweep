# The flags --delete-deployments and --delete-unused-environments

## Rule

`--delete-deployments` and `--delete-unused-environments` are write flags in each named repository, as [ADR-0008](ADR-0008.md) says.

`--delete-deployments` reads `--older-than` and `--keep` and needs one of them. In each environment the newest `--keep` deployments stay, and at least the newest one. For each selected deployment the tool posts the status `inactive`, then deletes the deployment.

`--delete-unused-environments` deletes each environment with no deployment. With `--older-than N` it also deletes each environment whose newest deployment was created more than N days ago. It needs no filter. The environment name is escaped for the path.

## Why

The owner asked to remove old deployments and unused environments. The newest deployment of an environment can be the active one, and the page of the environment shows it, so it stays. The REST API deletes only an inactive deployment when the repository has more than one, so the tool sets it inactive first. An environment with no deployment is not in use, so the flag needs no filter. An environment that only had old deployments can still be in use, so it is taken only when the owner gives `--older-than`.
