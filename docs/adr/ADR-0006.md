# The flags --retention-days and --actions-pr-approval change repository settings

## Rule

`--retention-days N` sets the artifact and log retention of each named repository to N days. GitHub applies this one value to checks, workflow runs, commit statuses, artifacts, and logs. N is 1 or more. The tool reads the maximum of each repository first, and a larger N changes nothing in that repository.

`--actions-pr-approval allow|deny` sets "Allow GitHub Actions to create and approve pull requests" in each named repository. The tool reads the default `GITHUB_TOKEN` permission and writes it back unchanged.

The tool reads each setting before it writes it. It writes only a value that differs. It prints one line for each repository and setting: the old value, then `unchanged`, `would set`, or `set`, and the new value. With `--dry-run` it reads and writes nothing.

A settings flag needs repository arguments, `--mine`, `--org`, or `--user`. With none of them it is an error, and the tool calls no `gh`. A settings flag together with `--summary`, `--usage`, or `--artifact-list` is an error. An error in one repository goes to standard error, the next repository still gets its change, and the exit status is 1.

The calls go through `internal/gh`, as [ADR-0001](ADR-0001.md) says. The flags open no checklist and send no delete request.

## Why

A flag is a public name, as [ADR-0003](ADR-0003.md) says. The owner asked to set these settings in one or many repositories. The tool refuses an empty target, because the default target of the reports is every repository of the logged-in user, and a write there needs an explicit choice. A per-repository error does not stop the run, so that the output shows which repositories changed. A PUT that leaves out `default_workflow_permissions` was not chosen, because the API description does not say that GitHub keeps the old value.
