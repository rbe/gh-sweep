# One action list for the write flags and the action menu of the checklist

## Rule

The package `internal/sweep` holds each write flag and each read-only flag as one `Action`. An action names its flag, the filters it reads, and a function that gives its entries. An entry has its line, what it counts in the total, and its write. The command line and the checklist read the same actions. Neither copies the selection rule, the line, or the filter check of an action.

`sweep.SetFilter` parses a filter value, and `Action.CheckFilters` checks the filters and the target. The command line and the filter form of the checklist call both, so both refuse the same input with the same text.

`m` on the project list opens the action menu for the marked repositories, or for the repository under the cursor. The menu shows a filter form, then a preview of each entry with its dry-run line. Only the checked entries run, after a confirmation. More than 20 entries, 1 GB or more, or more than one repository asks for the typed verb of the action. `--dry-run` sends no write. The result lists each entry done, the total line, and each failed entry.

## Why

The owner asked that every action of the command line is in the checklist, with its filters. One action list keeps the two in step: a new flag needs one `Action`, and the menu offers it. The confirmation follows the wipe rule of the checklist, because a write of [ADR-0008](ADR-0008.md) has no undo.
