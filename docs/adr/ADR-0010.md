# The flags for releases, package versions, and codespaces

## Rule

`--delete-releases` and `--delete-release-assets` are write flags in each named repository, as [ADR-0008](ADR-0008.md) says. They read `--older-than` and `--keep`, and need one of them. `--keep N` keeps the newest N releases by creation time. `--delete-releases` deletes the release and keeps its tag. `--delete-release-assets` deletes the assets and keeps the release, and it skips an immutable release.

`--delete-package-versions` runs once for one package. It needs `--package NAME`, a `--package-type` of the GitHub Packages API, and `--mine` or `--org NAME`. Repository arguments and `--user` are an error. It needs one of `--untagged`, `--older-than`, and `--keep`. The newest version always stays. A version with the tag `latest` always stays too. It is the last image that the default branch published, and it stays until another default-branch build moves `latest`.

`--delete-codespaces` runs once for the logged-in user. It needs `--mine` or repository arguments, and `--org` and `--user` are an error. It takes only codespaces with the state `Shutdown` and with no uncommitted and no unpushed change. `--older-than` compares the last use. A `kept:` line counts the stopped codespaces that stay because of such changes.

`--dry-run` writes nothing. The calls go through `internal/gh`.

## Why

The owner asked for old package versions, releases and release assets, and stopped codespaces. A codespace with unsaved work holds work that exists nowhere else, so the tool never takes it. The newest package version stays, so that a filter cannot empty a package. The Packages REST endpoints do not accept a fine-grained token, as the GitHub data file `fine-grained-pat.json` shows. The README says so. Declined: a guard against the platform versions of a multi-platform image, because it needs a read of each image manifest through the container registry, which is not the REST API of `gh api`. The README warns instead.
