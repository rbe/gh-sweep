# The preferences screen and the preferences file

## Rule

`internal/project` owns the preferences in force. They are seven values: `old_artifact_days` (default 5, 1 to 400), `large_artifact_bytes` (default 52428800), `advice_top_repositories` (default 3, 1 to 50), `keep_newest` (default 3, 1 to 1000), `retention_days` (default 90, 1 to 400), `confirm_entries` (default 20), and `confirm_bytes` (default 1073741824). No other package keeps a copy of these values or a constant for them.

The file is `gh-sweep/preferences.json` in the user configuration directory of Go `os.UserConfigDir`. It is one JSON object with these keys. A missing file gives the defaults. A missing key keeps its default. An unknown key, bad JSON, or a value out of range stops the tool with status 1 and an error that names the path, before the first gh call. The checklist writes the file with every key, mode 0600, in a directory with mode 0700.

`p` on the project list opens the preferences screen with one field for each value. A size field reads bytes, or a number with `KB`, `MB`, or `GB`. Enter checks every field, writes the file, and puts the values in force. A wrong value keeps the screen open, names the key, and changes nothing. Esc changes nothing. If the tool found no configuration directory, enter puts the values in force until the tool quits.

The prompt of `o` starts with `old_artifact_days`, and the prompt of `t` with `keep_newest`. The field `retention-days` of the action menu starts with `retention_days`. The typed confirmation of the checklist and of the action menu uses `confirm_entries` and `confirm_bytes`. The reports of [ADR-0018](ADR-0018.md) use `old_artifact_days`, `large_artifact_bytes`, and `advice_top_repositories`.

## Why

The owner asked that the values and retention times are configurable in the checklist. A file keeps a change for the next run, and the command line reads the same values, so a report and the screen agree. The file is a storage format, so it is expensive to reverse. Options not chosen: a flag for each value, because the owner asked for the checklist. Values for this run only, because the next run would forget them.
