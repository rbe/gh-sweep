# The advice report, the large-artifact mark, the report filters, and the workflow of an artifact

## Rule

A large artifact is an artifact of the large size or more, 50 MB (52428800 bytes) by default. An old artifact is an active artifact created more than the old days ago, 5 by default. [ADR-0019](ADR-0019.md) makes both values preferences.

`--advice` is a report flag. `--format` and `--output` of [ADR-0017](ADR-0017.md) work with it, like with `--summary`, `--usage`, and `--artifact-list`. Only one report flag is allowed. It prints numbered lines and a total line, then exits, and it sends no delete request:

1. The largest repositories with their sizes, largest first: 3 by default, as the preferences of [ADR-0019](ADR-0019.md) set.
2. The count and the size of the expired artifacts, and the key `x` that selects them.
3. The count and the size of the old artifacts, and the key `o` that selects them.
4. The count and the size of the large artifacts, and the flag `--retention-days`.

A line with a count of 0, or with no repository, is left out. When every line is left out, the report prints one line `no advice: no expired, old, or large artifact, and no storage`. The total line gives the number of read repositories and their size. Skipped repositories follow [ADR-0007](ADR-0007.md). With `--format json` or `csv`, the rows have the keys `advice`, `count`, `bytes`, `text`, and the total has `repositories` and `bytes`. `advice` is `largest-repositories`, `expired`, `old`, `large`, or `none`.

`--artifact-list` shows the workflow of each artifact. The tool reads the name of each workflow run once with `gh api repos/OWNER/REPO/actions/runs/ID`. If GitHub answers 404, or gives no name, the workflow is `-`. Any other error skips the repository, as [ADR-0007](ADR-0007.md) says. The text line puts `workflow NAME` after the id. A large artifact ends its line with `, large`. The JSON and CSV rows get the key `workflow` after `id`, and the key `large`, `true` or `false`, after `status`. In JSON an unknown workflow is `null`, and in CSV it is empty. The checklist reads no workflow, so the screen `i` shows no workflow part.

`--min-size` takes a size in bytes, or a number with `KB`, `MB`, or `GB` (1024 each). It works only with `--artifact-list`. The list then shows only the artifacts of that size or more, and the total line counts only those artifacts.

`--top` takes a whole number of 1 or more. It works only with `--usage`. The report then shows only the N largest repositories. The total line and each share still count every read repository.

`--min-size` or `--top` with another report flag, or without one, exits with status 2.

In the checklist, the row of a large artifact ends with `large` in the warning color, like `expired`.

## Why

The owner asked for the ideas 3 to 6. The owner set the age of an old artifact to 5 days. The agent chose the limit of 50 MB. The total of `--top` counts every repository, so the share of a shown repository stays the same with and without `--top`. Options not chosen: a workflow column in the checklist, because it needs one more call for each run on every load. A list of all workflow runs, because a repository can have many thousands of runs and few artifacts. A separate advice section after `--usage`, because a script reads `--usage` and new lines there could break it.
