# The flag --delete-merged-branches

## Rule

`--delete-merged-branches` is a write flag in each named repository, as [ADR-0008](ADR-0008.md) says. It reads the default branch, the branches, and all pull requests. It deletes a branch only when a merged or closed pull request of the same repository has the branch as head and has the same head commit as the branch now. A branch stays when it is the default branch, when it is protected, or when an open pull request has it as head or base. The flag reads no filter flag. The branch name is escaped for each part between slashes.

## Why

The owner asked to delete branches whose pull request is merged or closed. The head commit check keeps a branch that got new commits after its pull request ended, because those commits are in no pull request. The open pull request check keeps a branch that is still in review or that another pull request targets. A filter is not required, because each deleted branch is tied to an ended pull request, and GitHub can restore the branch from that pull request.
