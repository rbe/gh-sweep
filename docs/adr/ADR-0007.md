# A report skips a repository that fails and finishes

## Rule

If `gh` gives an error for one repository during `--summary`, `--usage`, or `--artifact-list`, the tool skips that repository and reads the next one. An error for a part of the inventory, such as the caches only, also skips the repository. The report then prints its lines for the other repositories. Before the total line it prints one line for each skipped repository: `owner/name: skipped, ` and the first line of the error. The total line counts only the repositories that the tool read. After the report, standard error says how many repositories the report skipped, and the exit status is 1.

An error before the first repository, such as no login or no repository list, still stops the tool before it prints a report.

The lines of a repository that the tool read do not change. The checklist does not change.

## Why

The owner asked that one failing repository no longer stops the report. A run over 200 repositories then still gives the numbers of the other 199. The exit status 1 keeps a script from taking a partial report as complete. Two options were not chosen. A skipped line on standard error only: the report would not show which repository is missing. A zero line for the failed repository: it would look like a repository with no artifact.
