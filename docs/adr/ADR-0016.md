# The Go source layout and the import direction of the packages

## Rule

The repository root holds no Go file. `cmd/gh-sweep` holds only `main`, which calls `cli.Run`. Every other package is under `internal/`, one directory for each concern:

| Package | Concern | May import |
| --- | --- | --- |
| `cmd/gh-sweep` | the program entry | `internal/cli` |
| `internal/cli` | the flags, their checks, the reports, the settings change, and the run of an action | `internal/gh`, `internal/project`, `internal/sweep`, `internal/ui` |
| `internal/ui` | the checklist screen | `internal/format`, `internal/gh`, `internal/project`, `internal/sweep` |
| `internal/sweep` | the actions of the flags | `internal/gh`, `internal/project` |
| `internal/gh` | the calls of the GitHub CLI | `internal/format`, `internal/project` |
| `internal/project` | repositories, entries, filters, and lines | `internal/format` |
| `internal/format` | sizes, times, and refs as text | nothing of the project |

A new package, or a new import between packages, changes this table first.

## Why

The owner asked for a structure instead of Go files at the root. The table makes the import direction a checked rule: `cmd/gh-sweep/layout_test.go` fails on an import that the table does not allow, and on a Go file at the root.
